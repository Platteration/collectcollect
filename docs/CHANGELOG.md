# Unreleased candidate

This candidate targets a self-hosted, single-owner installation. Public publishing remains disabled. The project is MIT-licensed.

- Photo scans retain drafts, edited identifications, uncertainty and duplicate decisions across reloads. Confident results save automatically; uncertain results stay in the review inbox. Interrupted identification can be retried without adding a second card.
- Goals and wishlists track desired quantities, variants, budgets and acquisition progress. A physical copy counts once within a goal. Goals travel with full backups and Markdown downloads.
- Individual purchases can be corrected, including previously unknown costs. Purchases already used in sales keep their financial fields fixed until those sales are undone.
- Portfolio history now records holdings as they change. Existing collections begin at an explicit opening balance on upgrade; earlier holdings are not reconstructed. The separate price-history view continues to use today's quantities. Collection value changes include purchases and sales and are not investment returns.
- Cards: the portfolio chart is drawn the way a brokerage draws an account, on the recorded holdings history. The axis fits the range on screen instead of starting at zero, with a dotted rule at the value the window opened at; each range is read at one close per hour (1W), day (1M, 3M) or week (1Y), so a refresh of every card draws the day's move and not a staircase, and a collection too new to have closed a day is read at a finer bucket; a dashed line follows what the copies held cost (copies with a recorded cost on cards that have a price, at today's recorded average cost per copy), which the key under the chart can hide, and the tooltip says how far the value is ahead of or behind it. When cards were added, sold or first priced in a window, the change above the chart says how much of it was that and how much was prices moving, with the market's percentage, and the headline no longer carries a percentage of its own then. A card's page draws the price paid across its value chart. Nothing recorded is changed: no migration, and *Show price history of current holdings* keeps today's quantities and has no cost line. The shared value chart (also drawn by skins and the engine's apps) is unchanged unless it is asked for the fitted axis or the cost line, except that its right margin grows for long gridline labels and gridline labels are written out in full where the compact forms would repeat.
- Price refreshes have persistent progress, item-level results and retries for unfinished work. Grading comparisons label measured and estimated bounds separately and require observations on three distinct days for historical comparisons.
- Authentication rejects forged logout tokens, limits concurrent login attempts and binds sessions to password changes. **Existing sessions expire on upgrade; sign in again.**
- Backups stage a consistent database and photo snapshot. Restores validate and migrate a private staging copy before replacing live data; a recovery journal rolls back interrupted swaps. Keep a pre-upgrade full backup for rollback to an older application version.
- A photo the collection names but the uploads folder lacks no longer blocks a backup, a restore or a put-back: the backup leaves it out and names the card; a restore clears the reference on its staging copy and lists it. A restore waits for background single-card lookups instead of refusing over them. A rollback that finds two copies of a folder keeps both and records the pair; `/api/health` reports `database` from a real query rather than the file's existence.
- Steam imports apply the exact reviewed inventory snapshot. Display fonts are bundled so production builds do not need Google Fonts access.
- Both apps refuse requests for host names they were not deployed under (set `ALLOWED_HOSTS` for a domain behind a reverse proxy, which must pass the original `Host` through; the list replaces the default names) and refuse state-changing requests a browser sends from anywhere but the app's own origin, scheme and port included, with or without a password. The health route is exempt from the host list. **Behind a proxy that ends TLS, set `TRUST_PROXY` (with `X-Forwarded-Proto`), `APP_BASE_URL=https://…` or `COOKIE_SECURE=1`, or every write from the browser is refused.** A write to the JSON API that carries a body or declares a type must declare `application/json` (415 otherwise); a bodyless `DELETE` or action `POST` from a script needs no header, and uploads, restores and folder imports stay multipart.
- Both apps: an alert webhook's name is resolved inside the connection that posts to it, every address it answers with is checked, and each delivery has a connection of its own, so a DNS answer that changes after the check can no longer point the post at the server's own network. An address with a user name or password in it is refused at delivery.
- Both apps: eight coordinated palettes (teal, the default, and amber, sky, indigo, violet, plum, copper, slate) set the ground, panels and accent in light and dark, from a palette menu in the header as well as Settings; saved `theme` and `colorScheme` choices carry over. Gains, losses, chart series, artwork and grading labels keep their colours. A choice the browser will not store still applies to the page, with a note saying it cannot be saved; printing uses the light theme; the browser chrome follows the ground actually shown. The default teal's lines, muted text and raised surfaces shift slightly; panels, buttons and inputs have rounder corners, buttons and inputs are at least 2.5 rem tall, and keyboard focus draws a 2 px outline in the accent.
- Retro Games, Comics, Watches and Whisky: a saved theme and palette are applied before the first paint, as in the other two apps. The shared shell's inline script carried no nonce, so the content security policy refused it on every page and a saved dark theme or palette showed only once the app had started, after a flash of the app's own light colours. Settings now offers the same palette picker as the header.
- Sessions are signed with a random key kept in `session-secret` beside the data unless `APP_SECRET` / `SKINS_APP_SECRET` is set. **Existing sessions on installs without an explicit secret expire on upgrade; sign in again.** The key is not part of a backup, so a restore on another machine asks for the password once.
- Nine skins JSON routes cap their request bodies (hygiene against a runaway client; a cross-site page can no longer reach them at all).
- Cards: a price source is only believed when its best answer plausibly is the card (every word of the name, and the number or the set agreeing when given); a card that used to get a wrong price keeps its last known value instead. Editing what a card is forgets the product a source matched, and *Not this card* on the card page does the same and looks again.
- Cards: recording a grade, a condition or a manual price, or saving the Settings multipliers, revalues the card at once from the prices already fetched; a manual price changed past the alert threshold raises the price-move alert on save. A whole-collection refresh no longer reorders the collection. Scans and imports only merge a copy into a row with the same variant, language and condition; others are set aside for a decision. Returned grades are booked by the same price-key chain as the card page. Purchase and sale dates default to your own day, and a sale across several purchases is booked at its exact cost.
- Skins: an item's value is what the best market that pays out in money would hand over after its cut; Steam's wallet figure stands in only when nothing pays in money, labelled as such. **The inventory total steps down at the first refresh after upgrading**, since it used to sum the highest listing before fees; a price-move alert is not raised across that change. The wear, StatTrak and Souvenir multipliers, which nothing read, are gone from Settings. The spread page names the missing CSFloat key when only one cash market is asked.
- Skins: a Steam refusal pauses every Steam lookup for as long as Steam asks; every market call times out after twenty seconds; a restore tells a running whole-inventory refresh to stop rather than refusing. Steam imports read every page of an inventory and refuse one whose count disagrees with what arrived; a "can be traded again" alert fires once per lock, and comes back for a new lock; adding an item is one transaction.
- Both apps: the installable shell's service worker is versioned by the build, so the offline page and icons refresh after a deploy.
- Cards: a refresh that finds the same prices as last time marks that snapshot as checked instead of storing a copy, and staleness counts from the check; a source that has not answered in twenty seconds is abandoned, not merely ignored. The dashboard sums two figures per snapshot rather than parsing every summary, draws each card's outlook from its newest ninety snapshots (sending the chart thirty points of it), and shows twelve outlook charts before offering the rest. The collection page sorts by name, value or date and shows 120 tiles a page, with the totals over everything the filter matches; each photo has a small copy for the grid, made again after a restore. A card's Markdown file lists its newest thousand prices and says how many older ones the database holds. The Settings page no longer measures every photo on every visit.
- Cards: eighteen more JSON routes cap their request bodies (hygiene against a runaway client). Scryfall's answer must carry every word of a Magic card's name, so a misspelt name is no longer silently priced as the closest card Scryfall knows; correct the name to get a price. Both apps: files under `/_next/` carry the same security headers as pages. CI: every workflow action is pinned to a commit.
- Skins: a refresh that finds the same prices as last time marks that snapshot as checked instead of storing a copy, staleness counts from the check, and a spread that has not moved is not announced again until it does. The inventory page sorts by name, value or date and shows 120 tiles a page, with the totals over everything the filter matches. An item's Markdown file lists its newest thousand prices. An item added, edited or imported with a trade lock that had already ended is not announced as tradable again, and a Steam re-import that reads nothing new no longer reorders the inventory or rewrites its files. Four indexes back the inventory's order, the storage-unit filter, sale lots and alerts.
- Cards: every card can record its centering as border ratios (typed in, read off a report, or read from the photo, which now reports them as numbers); the grading outlook's best case and the photo's likely grade are capped at the grade each company's published centering limits allow, the 3D view places the print by the measurement, and two slabs with different cert numbers are never merged. A graded card's page links to the company's public report and holds what it says: the subgrades, TAG's score and breakdown, the population, and, with `PSA_API_TOKEN` set, PSA's record and scans fetched by cert number (`POST /api/cards/[id]/cert`); recording a returned grade takes the cert too. - Cards: sports cards are covered in place. A card can record its team, rookie flag, parallel or refractor, serial numbering ("12/99"), autograph and relic flags, and the four subgrades a BGS label prints, in the form, the card page, the CSV import and export, the Markdown files, photo identification and the scan inbox. PriceCharting searches carry the parallel, autograph and relic and rank the listing that names the parallel above the base card; changing a card's parallel, autograph or relic forgets the product a source matched. **In a spreadsheet, a `serial` column is now the card's serial number, not its cert number, and a `parallel` column is a parallel, not a variant; the CSV export gains columns after `manufacturer` and `cert_number`, so anything reading it by position shifts.** Seven columns are added to the database on upgrade; no action is needed.
- Retro games and comics: the grade-or-wait verdict is the card app's rule, so it reads one price a day and judges timing only from three different days (three refreshes in one afternoon used to read "Good time to grade"); a prime verdict is now headed "Near the best recorded premium" and says it compares recorded prices and predicts nothing. A restored item file's sale-lot cell of thousands of spaces is read in linear time (2.5 seconds for 2,500 spaces before).
- Both apps, carried over from the September security pass: `X-Forwarded-For` and `X-Forwarded-Proto` are read from the right — the entry your proxy appended, not the one a client typed — so a client behind `TRUST_PROXY=1` can no longer reset its own limits or fill someone else's; `TRUSTED_PROXY_HOPS` names more than one proxy and `COOKIE_SECURE` settles the cookie's `Secure` flag. Without a trusted proxy `X-Forwarded-Proto` is believed nowhere, not even through the request's address, which Next writes as `https` whenever that header so much as contains it, from any client: before, such a request got HSTS, a `Secure` cookie, and its https `Origin` accepted on a plain-http address. Responses send `Referrer-Policy: no-referrer`, `base-uri 'none'`, no `X-Powered-By`, and HSTS with `includeSubDomains`, also to a request sent to the https address `APP_BASE_URL` names (its name and port). No request body over 64 MB is accepted: Next was silently cutting every body past 10 MB short, so **restoring a backup larger than 10 MB used to fail, and the restore ceiling is now 64 MB (was 512 MB for cards, 256 MB for skins)**; a larger collection is restored by unpacking it with the app stopped. A restore refuses an archive whose database carries a view, a trigger the app does not create, or a price summary that is not JSON, and replaces every trigger and index with the app's own before writing to it. Stored values the write path would refuse (an unknown game, category or status, a photo name, link or colour that is not one) read back as known ones instead of breaking every page that lists them; in cards that includes a restored card's manual graded prices, provider ids and identification, read through the checks a saved one passes (a `null` manual price list made the card's own page answer 500 on every load, and `null` ids a set's checklist refresh 502). The login page no longer shows the navigation, the unread-alert count or the setup checklist to someone not signed in. A sign-out that cannot be recorded says so. `/api/health` also reports the version, and Settings has an About section. Each app warns at startup when it has no password.
- Both apps: sign in with Google, beside the password or in its place, for the Google accounts each app lists (`GOOGLE_ALLOWED_SUBS` / `GOOGLE_ALLOWED_EMAILS` for cards with `APP_URL`, `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`; the same names under `SKINS_` for skins). It ends in the app's own session cookie, so sign-out and *Sign out everywhere* work as before. Setting any `GOOGLE_` variable turns the gate on, even before the rest is set: until it is, nobody signs in with Google and the log says what is missing. **Turning sign-in with Google on or off, or changing who may use it, ends every session, the password's included; sign in again.** A gate with a password and no Google variables signs exactly as before, so upgrading ends no session. With Google and no password, an `APP_SECRET` / `SKINS_APP_SECRET` shorter than 32 bytes signs nobody in (the log says so): it would be the only secret in a session's signature. The log names the id of an account let in by its address, so it can be moved to the list of ids.
- Cards, carried over from the September security pass: uploads must be JPEG, PNG, WebP or HEIC by both the declared type and the decoded bytes (any other `image/*`, SVG included, is refused) and at most 50 megapixels. The audit is the shared gate, `node .github/audit/npm-audit.mjs`: the same `npm audit --omit=dev` against the lockfile, red on every high or critical advisory `.github/audit/accepted.json` does not accept (this repository keeps no list). Next.js is 16.3.8, past the advisories against 16.3.4 (the `next/og` remote code execution among them). `.npmrc` is gone, so npm warns rather than refuses under a Node older than 22.
- Both apps as websites: every response — pages, API answers, Next's own `/_next/` files, the not-found page (drawn for a missing `/favicon.ico` it used to carry no security header at all, and for a missing `/_next/…` path no policy), every refusal and every redirect — carries one measured header set. An address with a trailing slash is now redirected by the app rather than by Next, which did it before any header was set; only Next's own redirect for an address with a repeated slash or a backslash and its 500 for a `TRACE` request, and Node's own 400 for a method it does not know and 431 for headers past its limit, still leave without them. Cards draws a reference image only over https, which is all its `img-src` allows: an `http:` address (from a file, a spreadsheet, a restore or the API) is kept on the card and in its file and exports, and the card shows without a picture instead of a broken one and a policy violation. `Permissions-Policy` denies 28 features (the card app keeps the camera for scanning), and `Cross-Origin-Resource-Policy: same-origin` is new. The skins icon's SVG source moved beside the script that renders it and is no longer served at `/icons/icon.svg`. A whisky bottle number and a watch's service-history cell are read in linear time (a 200,000-character cell took 17 and 22 seconds).

A sign-out the server does not confirm is now said on the page rather than going to the login page while the browser is still signed in.

The four hobby apps' Add page has separate Take photo and Choose photos buttons (the one button used to open only the camera on Android), and their Settings page has a Go to list with Import on phones, which is why their last tab is now labelled More, as in cards and skins.
