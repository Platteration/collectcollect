# Security policy

## Reporting a vulnerability

Please report security issues privately rather than opening a public issue.

Use GitHub's private vulnerability reporting on this repository:
**Security → Report a vulnerability**. That opens a private advisory visible
only to the maintainers. Private reporting is a repository setting the owner
switches on; while it is off, that button is not there and the form reaches
nothing, so open an issue instead that says only that you have a security
report and how to reach you, with none of the details in it, and a private
channel will be arranged.

Include what you need to make the problem reproducible: the affected version
or commit, which app (cards or skins), the steps or input that trigger it, and
what you observed. A proof of concept helps but is not required.

This is a small project maintained in spare time, so there is no response-time
guarantee. Reports are read and acted on in order of severity.

## Scope

In scope: the code in this repository — both apps (`apps/cards`, `apps/skins`)
and the shared package (`packages/core`) — including anything it does with
input that comes from outside it: uploaded photos, imported spreadsheets and
Markdown folders, backup archives, Steam inventories, price-source responses,
webhook addresses, what Google sends back to a sign-in (and who the gate then
lets in), and user-supplied text rendered into a page — and each
app as a website: the response headers it sends on every answer, a page that
runs or loads something its content security policy should refuse, and any
file it serves that is not part of the site (README, "The website"). Anything
that can lose or corrupt the collection an owner keeps in it counts as the
highest severity.

Out of scope: vulnerabilities in third-party dependencies that are already
public and have an upstream fix, findings that require an attacker to already
control the device or account, and reports generated by a scanner with no
demonstrated impact. The apps are meant for one owner on their own machine or
private network, not as a service for other people; findings that assume a
multi-user deployment are read with that in mind.

Each app also answers `/.well-known/security.txt` with the same two ways in:
the private advisory form, then the issues page for while the form is off. Its
`Policy` is this file on `main`, and its `Expires` date is a year ahead at most
and is renewed before it lapses; each app's `tests/website.test.ts` fails once
it has.
